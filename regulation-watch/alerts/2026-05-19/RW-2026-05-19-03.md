WHAT CHANGED (<=4 sentences, plain English)
───────────────────────────────────────────────────────────────
IAB Europe's TCF v2.3 specification (released June 2025, mandatory from 28 February 2026) adds one mandatory structural change to every TC String: the "disclosedVendors" segment, which mathematically encodes the set of vendors that were actually presented to the user in the CMP interface, is now required in all new TC Strings rather than optional. This change responds directly to the March 2025 CJEU ruling and the May 2025 Brussels Court of Appeal judgment confirming that IAB Europe bears joint-controller responsibility for the TC String and that the prior architecture could not prove which vendors a user actually saw — the disclosedVendors segment closes that transparency gap. For CMPs, the practical obligation is to update their live installations to include the disclosedVendors segment in every TC String they generate from 28 February 2026 onward; TC Strings generated before that date without the segment remain valid, but any string generated after the deadline without the segment is considered non-conformant. Google has confirmed that AdSense, Ad Manager, and AdMob in the EEA/UK/Switzerland require TCF v2.3 compliance from this date and that non-compliant CMPs will have ad requests defaulted to Limited Ads serving.

ID-PRIVACY® IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [ ] Consent Banner               — No UI change required. The disclosedVendors segment is a TC String structural addition; the user-facing banner experience does not change (no re-surfacing of the UI is required by the spec).
  [ ] Cookie Classification ML     — No change.
  [ ] Consent Storage & Proof      — TC Strings stored in the consent log must be v2.3 format from 2026-02-28. Any pre-existing v2.2 strings stored before that date remain valid — do not migrate historical strings. Going forward, the consent storage layer must write and read v2.3 TC Strings including the disclosedVendors segment.
  [X] Consent Signals (GPC/TCF/GPP)— Core change. The TCF signal generation module must be updated to: (1) compute the disclosedVendors segment from the set of vendors displayed to the user in the CMP vendor list at the time of consent presentation, (2) encode this segment in the TC String using the IAB Europe v2.3 bit-field specification, (3) transmit the v2.3 string to the CMP API and to downstream vendor scripts. This is a code change to the TC String serialization library. Confirm whether ID-PRIVACY uses IAB Europe's open-source tcstring library or a custom serializer — if the former, upgrade to the v2.3-compatible release of that library.
  [X] Geo / Jurisdiction Routing   — No routing logic change, but the jurisdiction routing must be verified to only invoke TCF v2.3 string generation for EEA/UK/CH visitors where TCF applies. Confirm the TCF signal path is not accidentally triggered for US visitors.
  [ ] Vendor / SDK Governance      — The disclosedVendors segment encodes which vendors from the Global Vendor List (GVL) were shown to the user. The vendor governance module must correctly pass the "vendors shown" set to the TC String generator at consent-capture time. Confirm this data is available in the current architecture.
  [ ] DSR Engine                   — No change.
  [X] Audit / Logging              — TC Strings written to the consent log after 2026-02-28 must be v2.3 format. Add a log validation check: on consent record creation for EEA/UK/CH visitors, verify the TC String contains the disclosedVendors segment and log a "tcf_v23_string_valid: true/false" field. Any "false" within the TCF jurisdiction is an incident.
  [ ] Cross-border transfer        — No change.
  [ ] Tenant Config / Admin UI     — No new tenant configuration required. This is a platform-level implementation change.
  [ ] Documentation / DPIA / RoPA  — Update TCF compliance documentation to reference v2.3. Note for EU/EEA tenants: TCF v2.3 compliance does not guarantee GDPR compliance; the Belgian DPA's position on the TCF as a valid consent mechanism under GDPR remains subject to ongoing DPA and court proceedings.
