WHAT CHANGED (<=4 sentences, plain English)
───────────────────────────────────────────────────────────────
Two compounding changes have materialized since the last scan and together redefine California's GPC and consent-banner compliance floor. First, CCPA regulations effective 1 January 2026 upgraded the GPC visible-indication obligation in § 7025(c)(6) from discretionary ("may display") to mandatory ("shall display"): any business that processes opt-out preference signals must now show a visible on-screen indicator — such as "Opt-Out Request Preference Signal Honored" or a toggled button state — when a GPC-enabled browser visits the site; silent GPC honoring is no longer sufficient. The same regulation package codified that closing or navigating away from a consent pop-up without clicking an affirmative "I accept" equivalent does not constitute consent and is classified as a dark pattern, and it extended the definition of prohibited dark patterns to include any asymmetry in accept-vs-reject step count, urgency framing, or pre-selected opt-in defaults. Second, the California AG's $2.75 million Disney settlement (February 2026, the largest CCPA settlement in history) established a new enforcement-grade standard for GPC scope: when a user sends a GPC signal in a logged-in state, the opt-out must apply to the user's account across all linked services and devices — honoring GPC only for the single device or session that sent the signal is partial compliance and constitutes a violation.

WHO IS AFFECTED
───────────────────────────────────────────────────────────────
- Applicability test:  Any business subject to CCPA (>= $25M annual revenue, or >= 100,000 consumers' personal information processed per year, or >= 50% of revenue from selling personal information) that operates a website or app accessible to California residents. GPC scope requirement applies to any business that offers cross-device or multi-service accounts.
- DataSafeguard customers likely affected: Essentially all US enterprise and mid-market tenants that (a) use ID-PRIVACY's GPC signal handling module, and (b) have any account-based or logged-in user experience. Tenants running a "silent" GPC implementation (honors signal technically but shows no UI indication) are in breach of the new "shall display" rule effective 1 January 2026 — this is already live enforcement risk. Tenants with multi-service or multi-device architectures (streaming, e-commerce with apps, financial services) face the Disney cross-device scope requirement.
- Customer notice required: YES — urgent, within 14 days (by 2026-06-02). The GPC visible-indication requirement has been in force since 1 January 2026 and the CPPA has explicitly stated it will cite "silent implementation" as the enforcement pattern in the next wave. Customers with account-based products need specific guidance on the cross-device requirement.

ID-PRIVACY® IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [X] Consent Banner               — Two specific changes required: (1) Dark-pattern rule: the banner must not treat page close/navigation as consent — if ID-PRIVACY's banner allows any code path where a dismiss-X or overlay-click without an explicit accept/reject choice results in non-essential cookies being set, that path must be eliminated for California visitors. (2) GPC visible indication: when a California visitor arrives with GPC enabled, the banner (or a persistent UI element within the banner/preference center) must display a visible indicator that the GPC signal has been recognized and the opt-out is in effect. The indicator must be visible on the same page load — it cannot be buried in a preference center the user must navigate to.
  [ ] Cookie Classification ML     — No new classification requirements from this change specifically. Existing "sale/sharing" signal routing for California is unchanged in taxonomy.
  [X] Consent Storage & Proof      — The GPC visible-indication display event must be logged as a new proof-of-consent event: "gpc_signal_received", "gpc_opt_out_applied", "gpc_indicator_shown" (with timestamp, page URL, indicator type displayed). This closes the enforcement gap where a business claims it honored GPC but cannot prove it showed the indicator. For cross-device/account scope: if a tenant has an account-linkage API integration, the consent record must propagate the GPC opt-out to all linked account sessions, with a "gpc_propagated_to_account" log event.
  [X] Consent Signals (GPC/TCF/GPP)— Critical. The GPC module must be updated in two respects: (a) Visible indication: after detecting a GPC signal and applying the opt-out, the module must trigger a UI rendering event that surfaces the indicator element. The element must be rendered on first page load, not only on subsequent visits. This likely requires a new client-side event "gpc:indicator:rendered" that the banner SDK emits. (b) Cross-device/account scope: the GPC opt-out propagation must reach the tenant's backend if the user is in a logged-in state. ID-PRIVACY's server-side consent API must support a "propagate_to_account" flag that tenants can enable when they have cross-device account architectures.
  [X] Geo / Jurisdiction Routing   — The US-CA jurisdiction ruleset must be updated to include: (1) the GPC visible-indication requirement as a mandatory feature (not tenant-configurable off), (2) the dark-pattern prohibition on close-as-consent as a mandatory enforcement (not configurable), (3) the cross-device GPC propagation flag as a configurable feature gated on tenant having an account-linkage integration.
  [ ] Vendor / SDK Governance      — No new vendor-disclosure obligations from this specific change.
  [ ] DSR Engine                   — No new DSR rights created; the opt-out cross-device requirement is a GPC signal-handling obligation, not a new DSR category.
  [X] Audit / Logging              — New mandatory log events for California: "gpc_signal_detected" (with signal value, user-agent, page URL), "gpc_opt_out_applied" (with scope: session|account), "gpc_indicator_rendered" (with indicator element type and placement), "gpc_account_propagation_attempted" (with success/failure and account ID hash). Retain minimum 3 years per CPPA enforcement pattern.
  [X] Cross-border transfer        — No change specifically, but note: the GPC opt-out must suppress sale/sharing with third-party analytics and advertising SDKs including those outside the US. The existing cross-border transfer controls in the vendor SDK gating layer should already handle this, but audit for California visitors.
  [X] Tenant Config / Admin UI     — New mandatory (non-configurable-off) toggle: "GPC visible indication [US-CA]" — always ON for California routing. New optional toggle: "GPC cross-device / account propagation [US-CA]" — configurable, with a dependency flag requiring the tenant to confirm they have an account-linkage API integration. Config validation: if a tenant has account-linked consent architecture and this toggle is OFF, surface a compliance warning in the admin dashboard.
  [X] Documentation / DPIA / RoPA  — Update US-CA section of sample DPIA and RoPA to: (a) reference CCPA § 7025(c)(6) as amended (effective 2026-01-01) for GPC visible indication, (b) reference CA AG Disney settlement as the controlling enforcement statement on GPC cross-device scope, (c) add the dark-pattern prohibitions checklist (no close-as-consent, step symmetry, no urgency framing, no pre-selected opt-in).

DEPENDENCIES / BLOCKERS:

  - The CPPA has not issued formal written guidance on what the "visible indicator" must look like beyond the regulation text and the enforcement actions. The Disney settlement refers to the requirement in passing; PlayOn Sports enforcement confirms the obligation but does not describe a specific UI pattern. The suggested CPPA language ("Opt-Out Request Preference Signal Honored") is from the regulation preamble. Legal should confirm whether a preference-center toggle in the opted-out state satisfies the requirement or whether a page-level badge is required.
  - Multi-state GPC sweep (CA/CO/CT) is ongoing. Colorado and Connecticut GPC requirements are substantively similar to California's but do not yet have a formal visible-indication requirement. Watch for CO/CT rulemaking.
