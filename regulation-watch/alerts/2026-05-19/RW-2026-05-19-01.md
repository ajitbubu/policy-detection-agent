WHAT CHANGED (<=4 sentences, plain English)
───────────────────────────────────────────────────────────────
The ICO published the final version of its "Guidance on the use of storage and access technologies" on 29 April 2026, incorporating changes introduced by the Data (Use and Access) Act 2025 (DUAA) that came into force on 5 February 2026. The most significant substantive change is that five new categories of cookies and similar technologies are now exempt from the PECR consent requirement — covering technologies used (1) solely for transmission of a communication, (2) to provide a service the user explicitly requested, (3) to collect aggregate statistics for service improvement (analytics), (4) to improve or adapt the service's appearance to a user's stated preference, and (5) to identify a user requiring emergency assistance — but each exemption is strictly purpose-limited and the analytics and preference exemptions carry a mandatory "simple means of objecting" obligation. The finalized guidance adds two new sub-chapters not present in the draft: one clarifying what a "simple means of objecting" means for the exempt-but-objectable categories (organizations must proactively offer an easy, free objection mechanism and cannot rely on browser settings alone), and one addressing whether the same storage or access technology can lawfully be used for multiple purposes simultaneously (answer: only if each purpose independently qualifies under PECR, and mixing an exempt purpose with a non-exempt one requires consent for the whole technology). Separately, DUAA also increased the maximum PECR fine ceiling from GBP 500,000 to GBP 17.5 million or 4% of global annual turnover — a 35-fold uplift that brings PECR enforcement parity with UK GDPR.

───────────────────────────────────────────────────────────────
WHO IS AFFECTED
───────────────────────────────────────────────────────────────
- Applicability test:  Any organization that places or accesses storage/access technologies (cookies, pixels, fingerprinting, web storage, tag scripts) on devices of UK-based users, whether established in the UK or not.
- DataSafeguard customers likely affected: All tenants with UK-targeted web or app properties — estimated to be the majority of enterprise and mid-market tenants. Particularly affected: tenants using first-party analytics without consent (who may now qualify for the analytics exemption if properly scoped), and tenants using a single cookie for multiple purposes (who may now need to separate consent and exempt-purpose flows).
- Customer notice required: YES — by 2026-06-12 (approximately 6 weeks from today). Customers need to know: (a) the five new exemptions they may be able to use without a consent gate for UK visitors, (b) that any analytics exemption use requires a built-in "object" mechanism, (c) that mixing exempt and non-exempt purposes in a single technology requires consent for all, and (d) that PECR fines have increased 35-fold.

ID-PRIVACY® IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [X] Consent Banner               — New logic required: for UK visitors, cookies classified under one of the five DUAA exempt categories must be handled differently from the consent-required default. The banner must not prompt consent for truly exempt-only technologies (this would be unnecessary and potentially confusing). However, the analytics and preference exemptions require a visible, easy objection mechanism to be presented — this is a new UI element distinct from the consent toggle. Engineering must implement a UK-jurisdiction pathway that (1) identifies exempt-only technologies, (2) suppresses the consent gate for them, and (3) surfaces the objection mechanism. The "closing a banner navigates away = not consent" principle from CCPA has a UK PECR parallel here: do not treat page-level cookie acceptance as covering non-exempt non-consented technologies.
  [X] Cookie Classification ML     — The classifier must gain a new UK-specific label set mapping each detected technology to one of: "PECR-exempt-transmission", "PECR-exempt-requested-service", "PECR-exempt-analytics", "PECR-exempt-preference", "PECR-exempt-emergency", "PECR-consent-required". Mixed-purpose technologies (same cookie serving both exempt and non-exempt purposes) must be flagged as "PECR-mixed-purpose — consent required". This is a net-new classification axis that does not exist in the current EU/GDPR-centric taxonomy.
  [X] Consent Storage & Proof      — For technologies served under an exemption rather than consent, the proof-of-consent record schema must support a new record type: "PECR-exempt-basis" with fields for the applicable exemption category, the purpose declared, and (for analytics/preference) the objection-mechanism URL or element ID shown. This is necessary to demonstrate to the ICO that exemptions were properly applied.
  [X] Consent Signals (GPC/TCF/GPP)— The "simple means of objecting" for the analytics and preference exemptions is a new signal pathway distinct from GPC and TCF consent. ID-PRIVACY must define how an objection under this PECR mechanism is captured, stored, propagated to analytics SDKs, and reflected in the audit log. If a user objects via this mechanism, analytics cookies that would otherwise be exempt must stop firing — the exemption lapses on objection.
  [X] Geo / Jurisdiction Routing   — The UK PECR ruleset in the jurisdiction router must be updated to enable the five-exemption pathway. Currently, UK routing likely applies a GDPR-equivalent consent-for-all-non-essential model. A new UK_DUAA ruleset must branch from the existing UK ruleset, effective 2026-02-05 (already in force). Tenants must be able to toggle the exemption use per-category.
  [ ] Vendor / SDK Governance      — No new vendor-disclosure obligations created by this guidance specifically. Existing GDPR/UK GDPR vendor disclosure requirements still apply for the consent-required category.
  [ ] DSR Engine                   — No new DSR rights created by this guidance.
  [X] Audit / Logging              — New log events required: "PECR-exemption-applied" (with exemption category, technology ID, purpose declared), "PECR-objection-received" (with timestamp, technology ID, signal source), "PECR-objection-propagated" (vendor confirmation). ICO enforcement record-keeping recommendation: retain for minimum 3 years given the new fine ceiling.
  [ ] Cross-border transfer        — No change from this guidance.
  [X] Tenant Config / Admin UI     — New per-tenant toggle: "Enable PECR DUAA exemptions for UK visitors" with per-category checkboxes. Tenants must be able to declare which technologies they are relying on each exemption for. The admin UI must warn when a technology is mapped to both an exempt purpose and a non-exempt purpose (mixed-purpose alert).
  [X] Documentation / DPIA / RoPA  — UK DPIA template and RoPA must be updated to reflect: (a) the new legal basis options (PECR exemption categories), (b) the objection mechanism obligation, (c) the new fine ceiling. Sample privacy notice language for the "object to analytics" mechanism must be drafted.
