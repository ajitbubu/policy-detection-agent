WHAT CHANGED (plain English)
---------------------------------------------------------------
Prior rule: TCF 2.2 allowed the "disclosedVendors" segment in the TC string to be optional, creating ambiguity about whether a vendor had disclosed legitimate interest or obtained consent in a given session.

New rule: TCF 2.3 (specification finalized June 2025, mandatory from February 28 2026) makes the disclosedVendors segment mandatory in all TC strings. This removes the signalling ambiguity around legitimate interest representation. Additionally, TCF 2.3 removes legitimate interest as a permissible basis for advertising and content personalisation purposes (Purposes 3 and 4 in the TCF taxonomy), requiring those to be consent-only. Default consent values are prohibited; TC strings must reflect only explicit user decisions.

Why this matters for CMP: Any ID-PRIVACY tenant generating or consuming TC strings must be on TCF 2.3. If ID-PRIVACY's TC string generator still produces v2.2 strings, those strings are now non-standard and may be rejected by downstream DSPs and SSPs. The February 28 2026 deadline has already passed.

---------------------------------------------------------------
WHO IS AFFECTED
---------------------------------------------------------------
Applicability test:  All TCF-registered CMPs and vendors; any controller using a CMP to generate IAB TC strings for programmatic advertising in the EU/EEA. Applies wherever TCF is used as the consent signalling mechanism.
DataSafeguard customers likely affected: All customers using ID-PRIVACY's TCF/IAB integration module for programmatic ad consent signalling.
