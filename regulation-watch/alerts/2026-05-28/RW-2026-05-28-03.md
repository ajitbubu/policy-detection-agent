WHAT CHANGED (4 sentences, plain English)
───────────────────────────────────────────────────────────────
TCF v2.3 makes the "disclosedVendors" segment of the TC string mandatory in all newly created
TC strings; in TCF v2.2 and earlier this segment was optional and most CMPs omitted it.
The segment encodes a bit vector indicating which vendors were actually disclosed to the user
in the CMP interface at the time the consent was captured, enabling downstream ad-tech vendors
to verify they were disclosed before processing data under Special Purposes. This change was
driven by the CJEU's March 2025 ruling and the Brussels Court of Appeal's May 2025 judgment,
which established that IAB Europe is a joint controller for TC strings and that vendors must
verify their own disclosure status before relying on the string. TC strings created after
28 February 2026 without this segment are treated as invalid by IAB Europe and by Google's
ad infrastructure, which defaults such requests to Limited Ads (no personalised advertising),
creating immediate revenue impact for publishers running personalised advertising through
ID-PRIVACY-managed CMP integrations.

ID-PRIVACY IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [ ] Consent Banner               — No change to banner UI required (IAB Europe confirmed
                                     CMPs should NOT re-surface the consent UI solely for this
                                     change). Existing consent choices are valid.
  [ ] Cookie Classification ML     — No change.
  [X] Consent Storage & Proof      — The disclosedVendors segment must be derived from the
                                     vendor list that was presented to the user at the time the
                                     TC string was created. ID-PRIVACY must store a snapshot of
                                     the vendor disclosure set at consent-capture time and use
                                     it to populate the disclosedVendors bit vector when
                                     (re)generating TC strings for that user.
  [X] Consent Signals (GPC/TCF/GPP)— CORE CHANGE: TC string generation module must be updated
                                     to include the disclosedVendors segment in all newly
                                     created TC strings. Specifically:
                                     (a) Populate the DisclosedVendors field (segment type 3)
                                     from the snapshot of vendors disclosed to the user.
                                     (b) For existing TC strings (created before 2026-02-28):
                                     CMPs that stored the vendor disclosure snapshot may update
                                     those strings; CMPs that did not should wait for user
                                     renewal/re-consent before adding the segment.
                                     (c) For all new consent captures from today: include
                                     disclosedVendors in the emitted TC string immediately.
  [ ] Geo / Jurisdiction Routing   — No change (TCF applies to EU/EEA; existing routing handles
                                     this).
  [X] Vendor / SDK Governance      — Vendor list snapshot at consent time must be captured and
                                     stored per consent event. This means the CMP must record
                                     which version of the Global Vendor List (GVL) was active
                                     and which vendors were disclosed in the CMP UI at the time
                                     of consent. Existing vendor-list version logging (if any)
                                     must be extended to a full disclosed-vendor ID set.
  [ ] DSR Engine                   — No change.
  [X] Audit / Logging              — Add storage of `disclosedVendorSnapshot` (the set of
                                     vendor IDs from the GVL that were shown to the user) per
                                     consent event. This is both a TCF requirement and an
                                     evidentiary requirement under GDPR Art. 7 (burden of proof
                                     of consent).
  [ ] Cross-border transfer        — No change.
  [X] Tenant Config / Admin UI     — Tenants should be able to verify in the admin dashboard
                                     whether their current TC string output includes the
                                     disclosedVendors segment. Add a compliance indicator:
                                     "TCF 2.3 disclosedVendors: [compliant / not compliant]."
  [ ] Documentation / DPIA / RoPA  — Update TCF integration technical guide to document
                                     the disclosedVendors segment requirement.
