WHAT CHANGED (4 sentences, plain English)
───────────────────────────────────────────────────────────────
The CNIL finalised its recommendations on multi-device (cross-terminal) cookie consent on
18 December 2025 (published 16 January 2026), establishing the specific conditions under
which a single consent choice can be valid across multiple devices linked to the same
authenticated user account. Before this guidance, no CNIL-level framework existed for
cross-device consent; CMPs implemented cross-device consent ad hoc, risking invalidity of
consent signals on secondary devices. The new recommendations apply only in authenticated
("logged-in") environments where the user is signed into the same account across devices
(computers, smartphones, tablets, connected TVs); they do not apply to unauthenticated
browsing. Key requirements are: (a) the cross-device scope must be disclosed clearly and
specifically before consent is captured (consent given for a single device without cross-device
disclosure cannot be retroactively applied to other devices), (b) refusal and withdrawal must
have the same cross-device scope as acceptance — organisations cannot globalise consent while
requiring per-device opt-outs, and (c) implementing multi-device consent is optional; operators
who choose not to implement it continue to obtain per-device consent as before.

───────────────────────────────────────────────────────────────
WHO IS AFFECTED
───────────────────────────────────────────────────────────────
- Applicability test: Any operator offering cookie/tracker consent in authenticated
  environments where users access the same service on multiple devices, and targeting
  French users. Directly relevant to streaming platforms, e-commerce with accounts, SaaS
  products, publishing platforms with login, and any B2C service with cross-device identity.
- DataSafeguard customers likely affected: Tenants who (a) have implemented or plan to
  implement cross-device consent propagation through ID-PRIVACY (e.g. syncing consent
  choices across web, mobile app, and CTV for logged-in users), AND (b) have French users.
  Not all tenants; this is a targeted feature-level impact. Estimate 20-30% of enterprise
  tenants have or aspire to cross-device consent sync.
- Customer notice required: YES — advisory to tenants using cross-device consent features,
  explaining the CNIL's conditions. No hard deadline, but any tenant currently propagating
  consent across devices for French users without complying with these conditions is at risk.

ID-PRIVACY IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [X] Consent Banner               — If a tenant has enabled cross-device consent sync in
                                     ID-PRIVACY, the banner copy and disclosure layer must
                                     be updated for FR: add an explicit statement that "your
                                     choice will apply to all devices connected to your
                                     [service name] account." This disclosure is a prerequisite
                                     for the cross-device consent to be valid. Must be shown
                                     before consent is captured.
  [ ] Cookie Classification ML     — No change.
  [X] Consent Storage & Proof      — Cross-device consent records must store: (a) the account
                                     identifier (authenticated), (b) the explicit disclosure
                                     that cross-device scope was communicated, (c) all device
                                     IDs / session identifiers the consent was propagated to,
                                     (d) withdrawal events must be propagated back to all
                                     linked devices and recorded. Current per-device consent
                                     storage likely needs an account-level consent record
                                     linked to device-level records.
  [ ] Consent Signals (GPC/TCF/GPP)— No direct change; cross-device consent propagation
                                     through existing TCF/GPP signals must use the account-
                                     level consent record as the source.
  [X] Geo / Jurisdiction Routing   — Add `cross-device-consent-enabled` flag gated by:
                                     `jurisdiction == FR AND authEnvironment == true`. The
                                     feature must be off by default for unauthenticated
                                     sessions in France.
  [ ] Vendor / SDK Governance      — No change.
  [ ] DSR Engine                   — No new rights; withdrawal must be propagated cross-device
                                     (which should already be true if the consent is cross-device).
  [X] Audit / Logging              — Add cross-device consent propagation event log:
                                     `cross_device_consent_propagated` with source device,
                                     target devices, account ID hash, timestamp. Required for
                                     CNIL compliance evidence.
  [ ] Cross-border transfer        — No change.
  [X] Tenant Config / Admin UI     — New configuration option: "Enable cross-device consent
                                     (CNIL-compliant, FR authenticated environments only)."
                                     When enabled, tenant must configure: account identifier
                                     field, disclosure language, and device propagation scope.
  [X] Documentation / DPIA / RoPA  — Add cross-device consent processing activity to France
                                     DPIA template. Document account-level consent record
                                     design. Update implementation guide.

───────────────────────────────────────────────────────────────
RISK IF NOT ACTIONED
───────────────────────────────────────────────────────────────
The multi-device consent recommendation is legally binding guidance under CNIL authority.
Tenants who have implemented cross-device consent propagation without the prescribed
disclosure and symmetric withdrawal mechanism are relying on potentially invalid consent
for French users — meaning any downstream processing (personalised advertising, profiling,
analytics) based on that cross-device consent signal is without a valid legal basis under
GDPR. CNIL fine ceiling: EUR 20 million or 4% of global annual turnover. The reputational
risk is lower than CRITICAL alerts (implementation is optional and most tenants may not
have cross-device consent today), but enterprise tenants with logged-in environments are
the highest-value segment for CMP platforms and this is an increasingly common architecture.
The risk of silent invalidity of existing cross-device consent implementations is the
primary concern.
