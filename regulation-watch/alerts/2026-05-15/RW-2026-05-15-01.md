WHAT CHANGED
───────────────────────────────────────────────────────────────
The ICO published its final Storage and Access Technologies (SAT) guidance on 29 April 2026, replacing the previous "cookies guidance" entirely and expanding scope to cover all tracking technologies — cookies, tracking pixels, device fingerprinting, web storage APIs, and tag-based scripts — under a single PECR/UK-GDPR framework. The guidance codifies the five new consent-exempt categories introduced by the Data (Use and Access) Act 2025 (effective 5 February 2026): (1) communication transmission, (2) user-requested service delivery, (3) first-party-only statistical/analytics (strictly not feeding advertising), (4) appearance/preference customisation, and (5) emergency assistance. Two new sub-chapters clarify (a) what constitutes a "simple means of objecting" and (b) how to handle mixed-purpose SATs — technologies serving both an exempt and a non-exempt purpose still require consent for the non-exempt element. The prior rule allowed only three exemptions (strictly necessary, security, preference-saving); the new rule adds two additional exemptions (analytics and appearance/customisation) and resets the compliance baseline for UK-specific CMP configuration.

ID-PRIVACY® IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [X] Consent Banner               — UK jurisdiction ruleset must expose the five DUAA-exempt categories as consent-free by default; mixed-purpose SATs (analytics + advertising) still require consent and must not be lumped with the exempt analytics bucket. The "simple means of objecting" sub-chapter may require a visible objection control for SATs set on a legitimate-interest basis (where applicable under UK GDPR Art. 6(1)(f)) on the first interaction layer.
  [X] Cookie Classification ML     — Classifier must now label tracking pixels, device fingerprinting tokens, and web storage keys alongside cookies; the existing cookies-only taxonomy is too narrow. The five exempt categories need corresponding classifier labels so the platform can auto-suggest exempt vs. consent-required for UK tenants. Mixed-purpose detection (same SDK serving analytics + advertising) needs a new flag.
  [ ] Consent Storage & Proof      — No change to proof-of-consent schema; exempt categories do not need a consent record, but the classifier label justifying the exemption should be stored for audit purposes.
  [ ] Consent Signals (GPC/TCF/GPP)— No direct change; GPC is not yet a recognised UK opt-out signal under PECR.
  [X] Geo / Jurisdiction Routing   — UK ruleset update required: add the five DUAA-exempt categories with the mixed-purpose restriction guard. These exemptions must NOT propagate to EU/EEA routing (where only the three original strict-necessity categories apply under the ePrivacy Directive).
  [X] Vendor / SDK Governance      — Vendor catalogue must be extended to cover tracking pixels (e.g., Meta Pixel, LinkedIn Insight Tag), device fingerprinting SDKs (e.g., FingerprintJS), and web storage (localStorage/sessionStorage scripts). Per-vendor mixed-purpose flags are needed so the platform can route correctly.
  [ ] DSR Engine                   — No new rights created; existing SAR/DSAR flow unchanged.
  [X] Audit / Logging              — Audit logs should record the exempt-category label applied to each SAT placement, to support evidence of compliance with the purpose-limitation requirement for the analytics exemption (first-party only, not fed to advertising).
  [ ] Cross-border transfer        — No change.
  [X] Tenant Config / Admin UI     — New UK-specific exempt-category toggles per SAT type; mixed-purpose warning UI for tenants who classify an SAT as both analytics and advertising.
  [X] Documentation / DPIA / RoPA  — Update UK consent RoPA template to reflect: (a) analytics SATs placed under exempt basis, (b) mixed-purpose SATs still under consent basis, (c) extended SAT taxonomy (pixels, fingerprinting, web storage).
