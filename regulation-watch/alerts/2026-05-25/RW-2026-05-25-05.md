WHAT CHANGED (plain English)
---------------------------------------------------------------
IAB Europe released TCF v2.3 on 19 June 2025. The single mandatory
structural change is that the disclosedVendors segment of the TC
string, previously optional, is now mandatory for all TC strings
created from 28 February 2026 onward. This segment records which
vendors were actually shown in the CMP UI, resolving prior ambiguity
where a vendor could claim legitimate interest without having been
disclosed to the user. TC strings generated after 28 February 2026
without the disclosedVendors segment are treated as invalid by all
TCF participants. TC strings generated before that date remain valid.
There is no UI re-surfacing requirement; the change is in the string
generation logic only. This is a CMP-layer code change: the TC string
encoder must include the disclosedVendors bit-field populated with
the actual set of vendors shown in the consent layer.

---------------------------------------------------------------
WHO IS AFFECTED
---------------------------------------------------------------
Applicability test:  All CMPs that generate TC strings under IAB
                     TCF (typically for EU/EEA publishers and any
                     platform that passes consent to Google Ad
                     Manager, AdSense, or AdMob, or to any TCF-
                     registered vendor).
DataSafeguard customers affected: All ID-PRIVACY customers using
                     the IAB TCF integration. Non-adoption means
                     generated TC strings are invalid, causing ad
                     requests to default to "Limited Ads" for
                     Google monetisation paths and potential loss
                     of programmatic revenue > 50%.
Customer notice required: YES -- if not already done (deadline
                     passed 2026-02-28). Any customer still on
                     TCF 2.2 output is generating invalid strings.

---------------------------------------------------------------
ID-PRIVACY IMPACT
---------------------------------------------------------------
Affected subsystems:

  [ ] Consent Banner
      No UI change required. The disclosedVendors segment is a
      string-encoding change, not a banner change.

  [ ] Cookie Classification ML
      No change.

  [ ] Consent Storage & Proof
      TC string stored in consent records must use v2.3 format.
      Historical v2.2 strings remain valid and do not need
      retroactive migration.

  [X] Consent Signals (GPC/TCF/GPP)
      TC string generation must include the disclosedVendors segment
      (bit-vector of vendors shown in the CMP UI). The TC string
      encoder/decoder must be upgraded to TCF v2.3 spec. Confirm
      that the ID-PRIVACY TCF string builder: (a) populates
      disclosedVendors with the current vendor list shown to the
      user, (b) outputs specVersion=2 and tcfPolicyVersion=5 per
      v2.3 spec, (c) correctly handles the case where a vendor was
      in the global vendor list but not shown in the CMP UI
      (disclosedVendors bit = 0).

  [X] Vendor / SDK Governance
      Vendor list management must track which vendors are shown in
      the CMP UI per consent session to correctly populate the
      disclosedVendors segment. This requires the vendor display
      set to be passed to the TC string builder at consent-record
      time.

  [ ] DSR Engine
      No change.

  [X] Audit / Logging
      TC string version should be logged in consent records to
      distinguish v2.2 and v2.3 strings for audit purposes.

  [ ] Cross-border transfer
      No change.

  [X] Tenant Config / Admin UI
      If any tenant is still configured to generate TCF v2.2 strings
      (e.g., via a version toggle), that toggle must be removed or
      forced to v2.3. Notify tenants using the TCF integration.

  [ ] Documentation / DPIA / RoPA
      Update TCF integration documentation to reference v2.3.

RISK IF NOT ACTIONED
---------------------------------------------------------------
TC strings generated without the disclosedVendors segment are invalid
per IAB TCF governance rules. For customers using Google Ad Manager /
AdSense / AdMob, invalid TC strings cause ad requests to fall back to
"Limited Ads," which can reduce programmatic revenue by more than 50%.
This is a direct commercial impact on publisher customers. IAB Europe
can also suspend CMPs from the Global CMP List for persistent
non-compliance, which would effectively disable the TCF integration
for all affected customers.
