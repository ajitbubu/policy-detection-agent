---------------------------------------------------------------
WHAT CHANGED
---------------------------------------------------------------
Prior rule: no CNIL guidance existed specifically on cross-device/multi-
terminal cookie consent. Consent collected on one device (e.g., desktop) was
implicitly device-specific; there was no regulatory framework for sharing or
propagating that consent to other devices of the same user.

New rule (CNIL Deliberation 2025-131, final recommendations published January
2026): the CNIL establishes a voluntary but highly prescriptive framework for
multi-terminal (cross-device) cookie consent. If a CMP chooses to implement
cross-device consent propagation, it must comply with these rules: consent
can only be shared across devices in authenticated/logged-in environments;
the multi-terminal scope must be disclosed to the user at the first layer of
the consent banner; a consent given on device A before the cross-device
mechanism was implemented cannot be retroactively extended to device B; the
symmetry principle requires that if consent can be accepted once for all
devices, it must also be withdrawable once for all devices; and when a user
authenticates on a new device not yet linked to their consent record, an
ephemeral notification banner must appear informing them of the existing
cross-device consent scope.

---------------------------------------------------------------
WHO IS AFFECTED
---------------------------------------------------------------
Applicability test:  Any controller or CMP operator that processes cookie
                     consent for users with accounts and serves French-
                     resident users — or any EU operator following CNIL
                     guidance as a DPA benchmark.
DataSafeguard customers likely affected:  Tenants in media groups, e-commerce
                     platforms, or multi-brand environments who have user
                     account systems and wish to implement cross-device
                     consent. Also relevant to any tenant whose current CMP
                     implementation propagates consent across devices without
                     this framework (they should be advised to stop or comply).
Customer notice required:  YES — advisory (not urgent compliance obligation).
                     Customers who are implementing or plan to implement cross-
                     device consent propagation must follow this framework or
                     face CNIL scrutiny. By 2026-08-01.

---------------------------------------------------------------
ID-PRIVACY® IMPACT
---------------------------------------------------------------
Affected subsystems:
  [X] Consent Banner               If cross-device consent propagation is
                                   enabled for a tenant, the first-layer
                                   banner must disclose the multi-terminal
                                   scope in clear language ("Your consent
                                   will apply across all devices where you
                                   are logged in"). An ephemeral banner must
                                   be shown on newly linked devices. Existing
                                   banner configurations that silently share
                                   consent across devices are non-compliant
                                   with this framework.
  [ ] Cookie Classification ML     Not directly affected.
  [X] Consent Storage & Proof      Cross-device consent architecture requires:
                                   (a) the consent record is associated with
                                   the authenticated account (not just device/
                                   browser), (b) the record includes a "scope:
                                   multi-terminal" attribute, (c) the record's
                                   "devices covered" list is maintained and
                                   updated when new devices are linked, (d)
                                   a withdrawal event on any device must
                                   propagate to all devices and be logged.
  [ ] Consent Signals (GPC/TCF/GPP) Not directly affected by this specific
                                   recommendation.
  [X] Geo / Jurisdiction Routing   France-routed tenants (and those using
                                   CNIL rules as default for EU) should have
                                   cross-device consent gated by this ruleset.
                                   A new "cross-device consent enabled"
                                   feature flag is needed per tenant, with
                                   France/EU defaults set to require full
                                   compliance with Deliberation 2025-131.
  [ ] Vendor / SDK Governance      Not directly affected.
  [ ] DSR Engine                   Withdrawal of consent must propagate to
                                   all linked devices — this interacts with
                                   the withdrawal/revocation flow in the DSR
                                   engine if consent withdrawal is handled
                                   there. Confirm the revocation API notifies
                                   all device sessions, not just the
                                   requesting device.
  [X] Audit / Logging              Add cross-device consent events to the
                                   audit log: device-link events, cross-device
                                   consent propagation events, ephemeral
                                   banner display events, and cross-device
                                   withdrawal events.
  [ ] Cross-border transfer        Not directly affected.
  [X] Tenant Config / Admin UI     New feature toggle: "Enable cross-device
                                   consent (CNIL multi-terminal framework)."
                                   When enabled, display configuration
                                   checklist requiring: (a) account-linkage
                                   confirmed, (b) first-layer disclosure text
                                   configured, (c) ephemeral banner on new
                                   device configured, (d) withdrawal
                                   propagation confirmed.
  [X] Documentation / DPIA / RoPA  Update France/EU tenant guide to cover
                                   cross-device consent. Add DPIA section on
                                   cross-device data flows. Advise tenants
                                   that implementing cross-device consent
                                   without this framework is now explicitly
                                   non-compliant in France.

RECOMMENDED ACTIONS
---------------------------------------------------------------
ENGINEERING (Abhishek's track):
  1. Scoping decision: determine whether ID-PRIVACY currently supports any
     cross-device consent propagation (implicit or explicit). If yes,
     audit against Deliberation 2025-131 requirements immediately.
     Est. 2 pts (audit) — by 2026-06-01.
  2. Architecture design: if cross-device consent propagation is to be a
     supported feature, design the account-linked consent record schema
     (account ID as the consent anchor; device list; scope: multi-terminal
     flag; per-device consent state). This is a material schema change.
     Est. 8 pts (design + implementation) — by 2026-08-01.
  3. Banner layer: implement the first-layer multi-terminal disclosure
     component and the ephemeral new-device notification banner as
     configurable options within the consent banner system. Est. 5 pts
     — by 2026-08-01.
  4. Withdrawal propagation: ensure consent withdrawal events fan out to
     all linked devices in the same account session. This may require a
     server-side push mechanism or polling for active sessions.
     Est. 5 pts — by 2026-08-01.
  5. Audit log extensions: add cross-device event types as above.
     Est. 2 pts — by 2026-08-01.

ML (Sumeet's track):
  No classifier changes required for this alert.

PRODUCT / LEGAL:
  1. Advisory to tenants currently implementing ad-hoc cross-device consent:
     notify them that CNIL now has a formal framework; advise them to
     configure their implementation against these requirements or disable
     cross-device propagation. By 2026-08-01.
  2. Legal review: confirm with French counsel whether Deliberation 2025-131
     is formally a "recommendation" (soft law) or creates a rebuttable
     presumption of non-compliance when violated. By 2026-07-01.
  3. Monitor CNIL's announced 2026 work on multi-property (cross-domain)
     consent guidelines — the next phase after multi-terminal. When that
     consultation opens, flag for a follow-up alert.

DEPENDENCIES / BLOCKERS:
  - Cross-device consent requires tenant-side user authentication and account
    linkage — ID-PRIVACY does not control tenant account systems. The feature
    must be an opt-in tenant configuration, not a default.
  - Primary CNIL source URL returned 403 on WebFetch; counsel should retrieve
    Deliberation 2025-131 directly from cnil.fr or the Journal Officiel
    before implementing the ephemeral banner and withdrawal propagation
    requirements, to confirm exact wording.

RISK IF NOT ACTIONED
---------------------------------------------------------------
CNIL fines for cookie violations reached EUR 486.8M in 2025. While this
recommendation is non-binding, CNIL has consistently enforced against
practices its recommendations prohibit. Any tenant silently propagating
consent across devices without the CNIL framework — including the first-
layer disclosure and withdrawal parity — is at risk of a CNIL sanction.
Fine ceiling under GDPR: EUR 20M or 4% of global annual turnover. The CNIL
specifically targets media groups and large e-commerce players; a
DataSafeguard tenant in those sectors is a plausible enforcement target.
