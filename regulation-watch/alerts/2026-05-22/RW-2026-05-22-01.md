WHAT CHANGED (plain English)
───────────────────────────────────────────────────────────────
The CPPA Board issued its first enforcement decision addressing a cookie-banner dark pattern and Global Privacy Control (GPC) failure in a student-data context. PlayOn Sports operated a consent banner that presented only an "Agree" option — no reject path — and on mobile blocked ticket redemption behind that "Agree" button, constituting a coerced consent dark pattern that violates CCPA. PlayOn also failed to honor GPC signals (its website did not recognise or act on the browser-transmitted opt-out preference signal), and it attempted to discharge its own opt-out obligation by pointing users to NAI/DAA third-party opt-out pages rather than operating a first-party mechanism. This decision establishes that (1) a consent banner with no functionally equivalent reject path is per se non-compliant, (2) GPC signal recognition is a mandatory CMP technical requirement under CCPA enforcement posture, and (3) directing users to third-party opt-out registries does not satisfy the operator's first-party CCPA opt-out obligation.

───────────────────────────────────────────────────────────────
WHO IS AFFECTED
───────────────────────────────────────────────────────────────
- Applicability test:  CCPA applies to for-profit businesses meeting any of: (a) gross annual revenues >$25 million, (b) buys/sells/receives/shares personal information of 100,000+ consumers or households, (c) derives 50%+ of revenue from selling personal information. The PlayOn order sets binding precedent on banner design and GPC for ALL such businesses targeting California residents.
- DataSafeguard customers likely affected: All tenants whose banners serve California residents — practically every commercial ID-PRIVACY tenant. The GPC-honoring obligation is already in CCPA regulations; this order confirms enforcement posture. Tenants whose CMP currently has accept-only or visually asymmetric first layers, or who rely on NAI/DAA opt-outs instead of a first-party mechanism, are directly in the firing line.
- Customer notice required:  YES — within 14 days. Tenants should be advised to (a) audit their banner first layer for reject-path parity, (b) confirm GPC signal recognition is active, (c) not rely on third-party opt-out registries as a substitute for first-party opt-out.

───────────────────────────────────────────────────────────────
ID-PRIVACY IMPACT
───────────────────────────────────────────────────────────────
Affected subsystems:
  [X] Consent Banner               — Must confirm that the US-CA jurisdiction ruleset enforces: (i) a "Reject All" / "Do Not Sell or Share" option on layer 1 with visual parity to "Accept/Agree"; (ii) no gate or paywall behaviour that conditions core site functionality on consent acceptance; (iii) mobile-responsive rendering that does not obscure the reject path behind the banner. If ID-PRIVACY's US-CA template does not already enforce these three points, it is shipping a non-compliant banner pattern. The order raises this from a "best practice" to an actively-enforced CPPA priority.
  [ ] Cookie Classification ML     — No change required.
  [ ] Consent Storage & Proof      — No new proof-of-consent fields required beyond existing schema, but GPC events must be logged (see Consent Signals below).
  [X] Consent Signals (GPC/TCF/GPP) — GPC recognition must be active and functional for all California-targeted properties. The CPPA confirmed that a site that does not parse and honour the Sec-GPC: 1 HTTP header is non-compliant. ID-PRIVACY must: (a) verify the GPC listener is enabled by default in the US-CA ruleset (not opt-in for tenants), (b) ensure the GPC signal results in an actual opt-out-of-sale-and-sharing record being written, not just a UI preference toggle, (c) log GPC-triggered opt-out events in the consent audit trail.
  [X] Geo / Jurisdiction Routing   — Verify that the US-CA jurisdiction profile mandates GPC recognition and layer-1 reject parity. If these are configurable on/off toggles, they must be locked ON for US-CA with no tenant override permitted.
  [ ] Vendor / SDK Governance      — No new vendor-governance obligation beyond existing CCPA service-provider chain rules. However: delegating opt-out to NAI/DAA was found insufficient — confirm ID-PRIVACY does not advise tenants to use third-party opt-out registries as their primary mechanism.
  [ ] DSR Engine                   — No new DSR right. GPC is a sale/sharing opt-out signal, not a DSR; already in scope.
  [X] Audit / Logging              — Add explicit audit-log event type `gpc_signal_honored` (with Sec-GPC header value, timestamp, jurisdiction, resulting opt-out record ID). Required for proving compliance with CPPA enforcement evidentiary standards.
  [ ] Cross-border transfer        — No change.
  [X] Tenant Config / Admin UI     — The US-CA ruleset configuration must expose whether GPC is enabled and whether layer-1 reject parity is enforced. Both should default ON and carry a warning if a tenant attempts to disable them.
  [X] Documentation / DPIA / RoPA  — Update the US-CA compliance checklist to reference the PlayOn order. Add a "GPC compliance audit" step in the tenant onboarding checklist.
