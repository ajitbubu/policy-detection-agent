WHAT CHANGED (plain English)
---------------------------------------------------------------
The UK Data (Use and Access) Act 2025 (DUAA) amended PECR in ways that came into
force on 5 February 2026. The ICO finalised its authoritative guidance implementing
those changes on 29 April 2026, after two consultation rounds (December 2024 and
July 2025).

Three engineering-relevant deltas:

1. FIVE NEW CONSENT EXEMPTIONS. The DUAA adds five statutory categories of storage
   and access technologies that no longer require consent under PECR (in addition to
   the pre-existing "strictly necessary" exemption). The five categories are:
   (a) transmission of a communication; (b) service the user explicitly requested;
   (c) statistical information to improve the service or website -- the analytics
   exemption; (d) adapting appearance to user preference; (e) emergency assistance.
   The analytics exemption (c) is the highest-impact item: first-party analytics
   cookies may now fire without consent in the UK, provided their SOLE purpose is
   improvement of the service and data is NOT shared with or used for advertising
   targeting. The ICO makes clear that a cookie used for analytics AND advertising
   does not qualify -- purpose must be exclusive.

2. SCOPE EXPANSION TO "INSTIGATORS." The DUAA extends PECR obligations beyond the
   party who literally sets or accesses the cookie to any party that "instigates"
   that storage or access. CMPs and tag managers that load third-party tags are now
   directly in scope, not just the publisher. This means ID-PRIVACY itself, as a
   CMP that orchestrates vendor tag firing, falls within PECR's reach when operating
   for UK-jurisdictioned clients.

3. "SIMPLE MEANS OF OBJECTING" FOR EXEMPT CATEGORIES. Organisations relying on the
   analytics or appearance exemptions must still provide a clear, free, simple
   mechanism for users to object. The ICO states that browser settings alone do NOT
   satisfy this; there must be an accessible, user-facing opt-out (e.g., a "Manage
   preferences" link that honours objections to analytics even where no banner is
   shown). If a user objects, the exempt activity must cease.

Prior rule: Cookie consent was required in UK under PECR for all non-strictly-necessary
cookies (Regulation 6), maximum PECR fine GBP 500,000.

New rule: Analytics and four other categories are now exempt from consent, but require
a "simple means of objecting." PECR fine ceiling raised 35x to GBP 17.5 million or
4% global turnover.

WHO IS AFFECTED
---------------------------------------------------------------
Applicability test:  PECR applies to any organisation using storage or access
  technologies on devices of users in the UK, regardless of where the organisation
  is established. As "instigator," this now explicitly extends to CMPs.
DataSafeguard customers likely affected:  ALL UK-jurisdictioned tenants, and any
  tenant whose websites or apps reach UK users. Estimated scope: most enterprise
  and mid-market tenants if they have any UK traffic.
Customer notice required:  YES -- two distinct notices needed:
  (a) Tenants currently showing an analytics-consent toggle in the UK banner may
      now suppress it (the analytics cookies are exempt), but MUST add an objection
      mechanism. Configuration change required, not just content change.
  (b) Tenants who are "instigators" of third-party tags (i.e., all CMP-managed
      tenants) need to understand they are now directly in PECR scope.
  Target notice by: 2026-06-10 (21 days from today).

ID-PRIVACY IMPACT
---------------------------------------------------------------
Affected subsystems:

  [X] Consent Banner
      UK jurisdiction ruleset must be updated to support a NEW banner mode:
      "analytics-exempt" -- no consent toggle for analytics cookies, but a
      persistent "Manage analytics preferences" link/button that fires an
      objection flow. This is a distinct UI state from the existing "consent
      required" and "consent not required" (strictly necessary) states. The
      existing two-state UK banner does not satisfy the new requirement.

  [X] Cookie Classification ML
      Analytics cookies in the UK context now need a sub-classification flag:
      "analytics-DUAA-exempt-eligible" (sole purpose = improve service, not
      shared with advertising). Cookies that straddle analytics + advertising
      must NOT be classified as exempt. The classifier must distinguish
      single-purpose from dual-purpose analytics cookies per vendor.

  [X] Consent Capture & Storage
      For UK-exempt analytics cookies: no consent record is captured (no
      consent needed). However, the objection mechanism requires storing
      objection signals per user per session/device. A new "analytics-objection"
      record type is needed alongside the existing consent record, so that the
      CMP can suppress analytics tags when a user has objected.

  [X] Consent Signals (GPC/TCF/GPP)
      TCF string for UK contexts must NOT encode analytics cookies as
      "consent required" if the exemption applies -- encoding a false consent
      requirement could mislead vendors. The UK TCF-string handling (already
      a separate UK-mode field) needs to be updated to reflect the exempt
      status, so that analytics vendors do not wait for a TC string consent
      bit that will never be set for UK-exempt purposes.

  [X] Geo / Jurisdiction Routing
      The UK jurisdiction ruleset must add a new DUAA-exemption mode flag.
      Logic: if visitor is UK, AND cookie is classified analytics-DUAA-
      exempt-eligible, AND sole purpose confirmed, THEN do not require consent;
      instead activate objection-mechanism flow. This is a net-new routing branch.

  [ ] Vendor / SDK Governance
      No direct change to vendor governance, but vendors whose analytics tags
      were previously gated behind UK consent will now fire without a consent
      bit -- operators need to verify vendor contracts still permit this (most
      DPA-to-DPA agreements do). Recommend advisory note to tenants.

  [X] Audit / Logging
      New log event needed: "uk-analytics-exempt-activated" (timestamp, cookie
      name, vendor, sole-purpose-flag), and "uk-analytics-objection-received"
      (timestamp, user session ref). These support ICO enforcement evidence
      requirements.

  [X] Tenant Config / Admin UI
      New per-jurisdiction toggle: "Enable DUAA analytics exemption (UK)."
      Default ON for UK-targeted tenants if their analytics cookies qualify.
      Tenants must be able to review their analytics cookies' "dual-purpose"
      flag before enabling. Also: add a "Sole purpose" attestation field in
      the cookie catalogue for UK analytics entries.

  [ ] DSR Engine            -- no change
  [ ] Cross-border transfer -- no change
  [ ] Documentation / DPIA / RoPA
      Update UK-specific CMP configuration guide and PECR compliance FAQ.
      Note the new "instigator" scope and the fine ceiling increase.
