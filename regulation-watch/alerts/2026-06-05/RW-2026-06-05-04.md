WHAT CHANGED
---------------------------------------------------------------
On 27 February 2026, the CPPA Board adopted a Stipulated Final Order requiring
youth sports ticketing platform PlayOn Sports (d/b/a GoFan) to pay a USD 1.1
million fine and implement remedial measures for two categories of CCPA violation:
(1) unlawful forced consent through a cookie banner that presented only an "Agree"
button, with no equivalent opt-out option, while blocking access to already-
purchased ticket functionality unless the user clicked "Agree" -- the CPPA
characterised this as an impermissible precondition on service delivery, not
valid consent; and (2) failure to provide a company-operated opt-out mechanism,
instead directing users to the Network Advertising Initiative (NAI) and Digital
Advertising Alliance (DAA) opt-out tools -- the CPPA confirmed these third-party
industry tools do not satisfy the CCPA/CPRA controller obligation to provide its
own "Do Not Sell or Share" opt-out mechanism. This is the first CPPA enforcement
action that directly sanctioned a cookie-banner pattern (no equivalent reject/opt-
out on the banner) and simultaneously confirmed the NAI/DAA redirect is legally
insufficient under CCPA. It establishes the de-facto compliance standard for cookie
consent banner design in California.

---------------------------------------------------------------
WHO IS AFFECTED
---------------------------------------------------------------
Applicability test:  Any CCPA-covered business (gross revenue > USD 25M, or
  processes PI of 100,000+ CA consumers, or derives 50%+ revenue from PI sale) that
  deploys a cookie consent banner to California users and/or relies on a "sale and
  sharing" opt-out mechanism.
DataSafeguard customers likely affected: Any tenant who: (a) uses a cookie banner
  that does not present an equivalent opt-out/reject option alongside the "Accept"
  option; or (b) relies on NAI/DAA links as a substitute for a platform-provided
  opt-out mechanism. These are common legacy patterns. Estimate: medium-to-large
  share of US-facing tenants.
Customer notice required: YES -- tenants whose banners currently lack an equivalent
  opt-out, or who use NAI/DAA redirects, are now on notice that this pattern has
  been fined. Platform should proactively identify and notify these tenants.

ID-PRIVACY IMPACT
---------------------------------------------------------------
Affected subsystems:

  [X] Consent Banner
      Primary impact. The order confirms two required banner properties for
      California (and by extension, any US state with CCPA-analogous opt-out rights):
      (a) OPT-OUT PARITY: A "Do Not Sell or Share" opt-out mechanism must be
          presented with equivalent accessibility and visibility to the "Accept"
          or consent option. A banner with only "Agree" (and no "Decline" or "Do
          Not Sell or Share") that conditions service access on clicking "Agree" is
          a CCPA violation. ID-PRIVACY's banner configurator must prevent tenants
          from publishing a US-CA banner that lacks an opt-out button. Recommend:
          add a hard validation rule that blocks banner publish if `jurisdiction ==
          US-CA` and no "opt-out" or "reject" action is configured.
      (b) NO SERVICE GATING: A banner that blocks core service functionality unless
          "Agree" is clicked is coercive and is not valid consent. ID-PRIVACY's
          banner implementation should not support "hard gate" mode (where the
          underlying page is blocked until consent) in CA-applicable rulesets
          without a co-equal opt-out path. Review whether any tenant currently has
          hard-gate mode enabled in a US-CA ruleset.
      Engineering note: the existing "reject all on first layer" requirement widely
      attributed to CNIL/EU now has a direct US-CA precedent; the same engineering
      implementation satisfies both.

  [ ] Cookie Classification ML
      No change -- classification categories are unchanged.

  [ ] Consent Storage and Proof
      No change to schema; existing CCPA opt-out proof fields are sufficient.

  [ ] Consent Signals (GPC/TCF/GPP)
      Indirectly relevant: the order confirms that platform-provided opt-out is
      required; GPC signal recognition remains separately required by CCPA/CPRA.
      No schema or code change from this order alone.

  [ ] Geo / Jurisdiction Routing
      No change; existing US-CA routing logic unchanged.

  [ ] Vendor / SDK Governance
      The order's finding that NAI/DAA redirects are insufficient for the
      "Do Not Sell or Share" obligation is relevant to any vendor governance
      workflow that currently documents a NAI/DAA link as a tenant's opt-out
      mechanism. Audit tenant configurations that have been configured with a
      NAI/DAA link as their only opt-out method and flag for remediation.

  [ ] DSR Engine
      The company-operated opt-out obligation is enforced at the banner level;
      no DSR engine change required.

  [X] Audit / Logging
      Add a banner-configuration audit log: when a tenant saves a US-CA banner
      configuration, log whether an opt-out action was configured. This creates
      a platform-side record that the opt-out parity check was in place.

  [ ] Cross-border transfer
      No change.

  [X] Tenant Config / Admin UI
      Two new validation rules in the banner configurator:
      (1) Hard validation: if `jurisdiction_ruleset == US-CA` (or any US state
          requiring CCPA-analogous opt-out), warn and block publish if no
          "Do Not Sell or Share" / opt-out button is configured. Error message:
          "A CCPA-compliant 'Do Not Sell or Share' opt-out button is required for
          California. CPPA enforcement (PlayOn Sports, March 2026) has confirmed
          that banners without an equivalent opt-out option are non-compliant."
      (2) Soft warning: if tenant has configured a NAI/DAA URL as their sole
          opt-out mechanism (in any US-CA ruleset), surface a warning that this
          is insufficient under CPPA PlayOn Sports enforcement and must be replaced
          with a platform-operated opt-out.

  [ ] Documentation / DPIA / RoPA
      Update US-CA consent guidance documentation to cite the PlayOn Sports order
      as the de-facto standard for opt-out parity and the company-operated opt-out
      obligation.

RISK IF NOT ACTIONED
---------------------------------------------------------------
The CPPA has demonstrated a willingness to issue seven-figure fines (USD 1.1M
PlayOn Sports; USD 2.75M Disney/ABC in February 2026 for a separate CCPA violation).
The cookie banner pattern at issue -- "Agree" only, no reject/opt-out, service
gated on "Agree" -- is widespread in legacy banner implementations. Any
DataSafeguard tenant operating such a banner in California faces direct exposure
under the standard the CPPA has now fined. The CPPA has also signalled continued
enforcement: California Attorney General and CPPA both listed 2026 as a heightened
enforcement year. If a tenant of ID-PRIVACY is fined for the same banner pattern
after ID-PRIVACY's own platform flagged it as permissible (e.g., by allowing
publish of a no-reject-button banner), DataSafeguard faces customer contractual
exposure and reputational damage. The banner validation rule (item 1 above) is a
low-effort, high-impact guardrail.
