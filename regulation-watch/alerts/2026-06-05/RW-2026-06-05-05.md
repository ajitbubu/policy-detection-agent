WHAT CHANGED
---------------------------------------------------------------
On 31 March 2026, the OAIC published an exposure draft of the Privacy (Children's
Online Privacy) Code 2026. The Code is mandated under the Privacy Act 1988 (as
amended by the Privacy and Other Legislation Amendment Act 2024) and must come
into force no later than 10 December 2026. The consultation period closes today
(5 June 2026). Key provisions: (1) Scope is broad -- covers apps, games, websites,
streaming platforms, and educational tools likely used by individuals under 18,
not only social media; (2) Age consent threshold -- children under 15 cannot
provide valid consent; parental/guardian consent must be obtained from someone
with "reasonably confirmed" parental responsibility; (3) Best-interests principle
-- collection, use, and disclosure of a child's personal information must be
consistent with the child's best interests; (4) Mandatory Privacy Impact
Assessments (PIAs) for high-risk processing involving children, with a PIA
register requirement; (5) Default privacy settings must be the most
privacy-protective option. The Code will layer on top of the existing Australian
Privacy Principles (APPs). This is still an exposure draft -- final Code may
differ from current draft.

---------------------------------------------------------------
WHO IS AFFECTED
---------------------------------------------------------------
- Applicability test:   Online service providers whose services are "likely
                        to be accessed by children" (broad functional test;
                        not limited to services explicitly targeting children).
                        Australian-establishment or targeting-Australian-users
                        test applies.
- DataSafeguard customers likely affected: Any customer with Australian
  operations whose platform, app, or website may be accessed by under-18s
  (very broad scope -- most consumer-facing digital products qualify).
- Customer notice required: YES -- customers with Australian consumer-facing
  operations should be flagged to monitor the Code finalisation and prepare
  age-gating and parental consent mechanisms. Recommend a horizon advisory
  within 90 days.

ID-PRIVACY IMPACT
---------------------------------------------------------------
Affected subsystems:
  [X] Consent Banner               -- Once in force: children under 15 cannot
                                      consent; ID-PRIVACY must support a parental-
                                      consent flow for AU-jurisdiction visitors
                                      to covered services. Age-gate UI required
                                      upstream of or integrated into the consent
                                      banner for covered services. This is a new
                                      banner variant (not a configuration of
                                      existing consent layer). Scope and design
                                      depend on final Code text.
  [ ] Cookie Classification ML     -- Not directly affected by the age-consent
                                      change; cookie categories unchanged.
  [X] Consent Storage & Proof      -- Parental consent for under-15s requires
                                      proof of parental responsibility
                                      ("reasonably confirmed"). Consent storage
                                      schema must support a `parental_consent`
                                      record type with guardian identifier field.
                                      Specific verification method TBD pending
                                      final Code guidance on "reasonably
                                      confirmed."
  [ ] Consent Signals (GPC/TCF/GPP)-- Not directly affected.
  [X] Geo / Jurisdiction Routing   -- AU ruleset: once Code is finalised and
                                      in force, services in scope must route
                                      to the age-gate / parental-consent flow.
                                      Admin toggle needed: "Children's Online
                                      Privacy Code (AU) -- enabled for this
                                      tenant" (off by default until Code is final).
  [ ] Vendor / SDK Governance      -- Behavioral profiling of children for
                                      marketing is prohibited under the draft
                                      Code. Vendor governance module should flag
                                      any vendor or SDK with marketing-profiling
                                      purpose as non-permissible for child
                                      visitor sessions under AU jurisdiction.
  [ ] DSR Engine                   -- Best-interests principle may limit
                                      data retention; no specific new DSR right
                                      introduced by the Code beyond existing APPs.
  [ ] Audit / Logging              -- Mandatory PIA register requirement; not
                                      directly an ID-PRIVACY logging feature,
                                      but PIA documentation support may be
                                      requested by customers.
  [ ] Cross-border transfer        -- Not affected by the Code specifically.
  [X] Tenant Config / Admin UI     -- New per-tenant toggle (described above)
                                      for AU children's Code once finalised.
  [X] Documentation / DPIA / RoPA  -- DPIA template for AU operations should
                                      add a "children's privacy" section once
                                      Code is final. PIA register support
                                      (customer-facing template) should be
                                      scoped.

RISK IF NOT ACTIONED
---------------------------------------------------------------
Risk at this stage is LOW (Code not yet final). If ID-PRIVACY does not prepare
now, there is a risk of a compressed implementation timeline once the Code is
published (as little as 30-60 days before the 10 December 2026 statutory
deadline). Customers offering consumer apps/games/streaming to Australians will
be in breach of the Code without an age-gating / parental-consent mechanism.
The Privacy Act 1988 (as amended) carries penalties up to AUD 50 million for
serious or repeated breaches. Reputational risk for DataSafeguard if customers
are not prepared.
