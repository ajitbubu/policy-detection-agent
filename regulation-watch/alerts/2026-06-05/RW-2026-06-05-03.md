---------------------------------------------------------------
WHAT CHANGED
---------------------------------------------------------------
IAB Europe has incremented the TCF Policy version from 5.0.a to 5.0.b and released
corresponding technical specification updates for public comment on 29 May 2026.
Three distinct changes are introduced: (1) Multi-device consent handling -- CMPs
must now propagate a user's authenticated-session consent signal across devices in
a manner aligned with CNIL's December 2025 cross-device consent recommendations,
meaning consent collected on one device must be recognisable and honoured when the
same authenticated user visits on another device, and the TC string must correctly
reflect this; (2) StandardTexts UI requirement -- CMPs are now required to display
the full standard feature explanation text (sourced from the GVL's new standardTexts
object) alongside feature names and standard user-friendly text in the consent UI,
replacing the current practice where some CMPs show only the short feature name; and
(3) Legacy LI-bit workaround removal -- the requirement for CMPs to set the
Legitimate Interest (LI) bit to 1 for vendors that declare only Special Purposes is
removed, because those vendors can now use the mandatory disclosedVendors segment
(introduced in TCF v2.3) to confirm disclosure. This is a minor TCF string behaviour
change.

---------------------------------------------------------------
ID-PRIVACY IMPACT
---------------------------------------------------------------
Affected subsystems:

  [X] Consent Banner
      The standardTexts requirement means the banner/preference centre must render
      a longer explanation text for each IAB TCF feature (e.g., "Actively scan
      device characteristics for identification") sourced dynamically from the GVL's
      new `standardTexts` object. This is a UI rendering change. Impact on banner
      readability/length should be UX-tested. The feature explanation text must
      appear alongside (not replace) the existing short feature name.
      Implementation dependency: GVL update with standardTexts object expected
      mid-July 2026; banner must consume it before the mid-October 2026 deadline.

  [ ] Cookie Classification ML
      No change -- classification categories are unchanged.

  [ ] Consent Storage and Proof
      No change to proof-of-consent record schema for the standardTexts change.
      For multi-device consent: if ID-PRIVACY propagates TC strings across devices
      for authenticated users, the propagation logic must align with the updated
      policy. The stored consent record itself does not change schema but the
      cross-device propagation event should be logged.

  [X] Consent Signals (GPC/TCF/GPP)
      Primary impact area:
      (a) Multi-device: TC string propagation across devices for authenticated users
          must be updated to match Policy 5.0.b requirements. This may require
          reading and re-serialising the TC string when a logged-in user switches
          devices, rather than issuing a fresh consent prompt.
      (b) LI-bit workaround removal: CMPs must stop setting LI = 1 for
          special-purposes-only vendors in the TC string. Any code path in the TCF
          string serialiser that currently implements this workaround must be
          removed. Risk: if not removed, the string will be out-of-spec from the
          mid-October deadline and vendors relying on the disclosedVendors segment
          will read a contradictory signal.

  [ ] Geo / Jurisdiction Routing
      No change -- TCF applies EU-wide; routing logic unchanged.

  [X] Vendor / SDK Governance
      Vendor metadata: vendors declaring only Special Purposes will no longer have
      an LI bit set to 1 in their string segment; downstream vendor integrations
      must not rely on that bit for special-purposes vendors after mid-October 2026.
      Update vendor metadata export/API to reflect the post-5.0.b LI-bit behaviour.

  [ ] DSR Engine
      No change.

  [X] Audit / Logging
      Log multi-device consent propagation events: `tc_string_propagated_across_device`
      with source device, target device, authentication context, and TC string hash.

  [ ] Cross-border transfer
      No change.

  [X] Tenant Config / Admin UI
      No new tenant-facing toggle required; the standardTexts rendering change and
      LI-bit fix are platform-level changes. Tenants should be notified via the
      dashboard that the banner UI will change (longer feature texts) from
      mid-October 2026.

  [X] Documentation / DPIA / RoPA
      Update TCF integration documentation to describe (a) the standardTexts GVL
      field and how it feeds the banner, (b) multi-device consent propagation
      behaviour, (c) the LI-bit workaround removal. No DPIA change required.

RISK IF NOT ACTIONED
---------------------------------------------------------------
CMP non-compliance with TCF Policy 5.0.b by the mid-October 2026 deadline results
in loss of TCF registration, which means ID-PRIVACY-generated TC strings are no
longer valid under the framework. Publishers using ID-PRIVACY as their CMP would
see programmatic revenues fall to "Limited Ads" (no personalised advertising),
which is commercially severe for adtech tenants. IAB Europe and IAB Tech Lab have
historically enforced deadlines (TCF v2.3 disclosedVendors mandate, February 2026,
was enforced; non-compliant strings were rejected by SSPs). The LI-bit workaround
removal creates an additional low-level risk: if the workaround code is left in
place after the GVL update, TC strings will contain a contradictory signal for
special-purposes-only vendors, potentially causing vendor-side consent-signal
errors that are difficult to debug in production.
